## 官方公开渠道与提交方法

[开放平台联系渠道](https://open.workbuddy.cn/docs/contact)公开列出咨询邮箱 **openworkbuddy@tencent.com**，并提供应用官方互助交流群二维码。

用户可亲自：

1. 打开上述官方页面再次确认邮箱。
2. 在自己的邮箱中新建邮件，收件人填写上述地址，复制下方主题和正文。
3. 检查不含密钥、Token、授权码、Cookie、私人配置或带授权参数的回调 URL 后自行发送。
4. 或自行扫描官方页面二维码入群咨询。不要把咨询文案当作应用注册申请；注册/接受协议/权限申请需要另行亲自处理。

## 可复制正文

主题：咨询个人开发者开源 Windows 本地应用接入 Local Assistant Open API 的资格、OAuth 与任务关联协议

WorkBuddy 开放平台团队您好：

我们正在开发开源本地多 Agent 协作项目 AI Team Runtime，希望在用户明确授权后，通过官方 Open API 调用该用户自己的 WorkBuddy PC 本地助理。当前 Windows 客户端为 5.8.3，尚未开展真实授权或 API 联调。

我们已阅读：

- https://open.workbuddy.cn/docs/openapi
- https://open.workbuddy.cn/docs/third-party-app

计划仅申请 user.localassistant.readable 和 user.localassistant.invokable，不提取桌面内部凭证，不使用 GUI 自动化或私有接口。希望确认以下事项，并请提供适用文档、完整字段定义及合成请求/响应示例：

1. **注册资格和应用类型**：个人开发者能否为开源 Windows 本地桌面工具申请这两个权限？应选择哪类应用？是否需要企业认证、额外资质、应用审核或软件签名？分享接入的企业条件是否独立于 Local Assistant？
2. **用户各自授权**：是否支持发布一个开源应用，由每位使用者授权自己的 WorkBuddy 账号？还是每位用户必须自行注册应用？是否有账号地域、套餐、客户端最低版本及多设备选择限制？
3. **OAuth 部署**：本地应用是否支持公共客户端、PKCE、系统浏览器和 localhost/127.0.0.1/[::1] loopback 回调？若支持，请说明协议参数、端口及回调注册规则。若不支持，是否必须部署独立公网服务器或固定域名？是否要求 HTTPS、备案或域名审核？
4. **密钥信任边界**：文档要求应用 secret 和 refresh token 放服务端。是否有适合纯本地开源应用的官方方案？受信任服务端应如何向本地应用提供短期访问能力，是否允许本地使用 Windows DPAPI 保存 access token？请明确禁止和允许的部署形式。
5. **请求与回复关联**：POST /localassistant/message 返回的 message_id 与后续 assistant 消息如何一一关联？GET 的 message_id 看起来是时间游标，如何排除同时发生的桌面操作、其他任务和其他设备消息？是否存在 reply_to、task_id、session_id 或官方等价字段？request_id 是否仅为 HTTP 追踪标识？
6. **增量读取规则**：消息顺序、分页/截断、同一消息内容更新、重复消息、游标推进及恢复读取规则是什么？是否支持独立会话和工作目录隔离？
7. **终态和取消**：哪个明确字段或事件表示本次任务成功完成、失败或取消？如何区分部分回复与最终回复、等待工具审批与执行结束？是否有正式取消接口及取消确认？请勿仅提供云端 tasks 的状态，需求针对 PC Local Assistant。
8. **Token 生命周期**：授权页的有效期说明与接口示例 expires_in 不同，应采用哪个契约？refresh 是否旋转、是否有重用检测/宽限期？用户如何撤销授权？有无公开撤销接口或通知？重新启动应用后如何识别已撤销授权？
9. **额度与幂等**：两个权限分别有哪些速率、并发、日配额和费用限制？是否有 Retry-After 或官方建议轮询间隔？提交超时、结果不确定时，有无幂等键或查询提交结果的机制，避免重复消耗模型额度？

当前实现只观察带随机标识的合成回显，不把 HTTP 200、收到消息或文本 APPROVE 当作任务完成。在官方关联与终态契约明确前，我们不会开启正式自动审核或三 Agent 工作流。

烦请告知符合上述场景的最小合法接入步骤、审批材料和后续技术咨询渠道。无需提供任何实际用户凭证；示例使用占位值即可。

谢谢。
